SECTION 0

伺服器種類

BMC 的功能深度通常取決於伺服器等級、應用場景與硬體複雜度。因此，理解伺服器分類有助於判斷 BMC 的管理需求。

依等級分類

等級常見定位主要特徵典型應用
低階 / Entry-level小型企業、實驗室、分店單 CPU、少量記憶體與儲存，管理功能較基本。檔案伺服器、小型網站、NAS、測試機、AD/DNS。
中階 / Mainstream企業主力平台1 到 2 顆 CPU、較多 DIMM、RAID、雙電源、完整 BMC。虛擬化、資料庫、ERP、Web service、CI/CD。
高階 / Enterprise關鍵任務、高可靠性多 CPU、大量記憶體、熱插拔、強 RAS、冗餘設計。金融、電信、核心資料庫、SAP HANA、大型虛擬化。
AI / HPCGPU 或加速器運算多 GPU、高功耗、高散熱、液冷、高速網路。AI training、AI inference、HPC、科學運算。
Edge Server邊緣場域短機身、耐溫、低功耗、遠端維運重要。工廠、零售、基地台、影像分析、IoT gateway。

Edge / Rugged Server部署在邊緣、工業、戶外或空間受限環境。可在較嚴苛環境運作，遠端維運價值高。擴充性通常較低。

SECTION 1

AI Rack 與高階 GPU 平台名詞

AI Rack 是針對 AI training / inference 設計的 整櫃級系統架構，不是單一零件，也不是單純一台伺服器。隨著功耗、散熱與高速互連規模提高，BMC 或 rack manager 需要管理 GPU tray、switch、retimer、CXL device、液冷系統等元件。

AI Rack整櫃系統架構一個 rack 內整合 compute node、GPU tray、switch、power shelf、液冷設備與 rack manager。
Data Center多櫃 / 機房多個 rack 組成 cluster 或資料中心。
AI Rack 是 rack-scale architecture，重點在於整櫃電源、散熱、高速互連與模組化維運。

SECTION 2

BMC 是什麼

BMC 是 Baseboard Management Controller，中文常譯為 基板管理控制器。它是獨立於主機 CPU 的管理晶片，常見於 server、storage、network appliance、AI server、telecom equipment 等需要遠端維運的設備。

獨立管理控制器

即使 host CPU 未開機，BMC 仍可透過 standby power 運作。

硬體監控中心

讀取溫度、電壓、風扇、電源、事件紀錄等硬體狀態。

遠端維運入口

提供 Web UI、Redfish、IPMI、KVM、SOL、遠端開關機等功能。

韌體更新橋樑

可更新 BMC firmware、BIOS/UEFI、CPLD、FPGA、SSD/NIC firmware。

BMC 是主機板上的獨立管理控制器，負責設備管理、監控、維護與故障恢復。

CPLD 是什麼

CPLD 是 Complex Programmable Logic Device，屬於可程式化邏輯元件。它通常放在主機板、server card、power board 或模組上，以硬體邏輯和狀態機處理需要快速、確定性高、即使主要軟體尚未啟動也必須運作的 Board-Level 控制工作。

Power / Reset Sequencing

依時序控制 power rail enable、power good、reset release 與關機流程，避免元件在電源尚未穩定時啟動。一般順序為 standby power → CPLD → BMC BootROM → U-Boot，因此 CPLD 通常早於 U-Boot 運作，實際仍依平台設計而定。

Glue Logic 與訊號整合

整合 GPIO、presence、fault、interrupt、strap、mux 與 LED 等離散訊號，補足不同晶片介面之間的 Board-Level 邏輯。

Board-Level 狀態與保護

即時偵測異常條件、鎖存 fault、保存簡單狀態，並在必要時直接觸發 reset、power off 或告警。

項目BMCCPLD
核心角色執行韌體與管理服務，負責監控、決策、事件紀錄、網路管理與遠端維運。執行可程式化硬體邏輯，負責低延遲、確定性的 Board-Level 控制與訊號整合。
典型工作Redfish/IPMI、sensor、SEL、KVM/SOL、inventory、firmware update。Power/reset sequencing、GPIO 邏輯、mux、presence/fault、LED、POST code 或 strap 控制。
常見連接透過 I2C/SMBus、GPIO、JTAG、SPI 或其他管理介面讀取狀態、下達命令及更新 CPLD image。直接連接 power controller、CPU/PCH、FPGA、卡槽與各種 sideband 訊號，並將狀態回報給 BMC。
分工心智模型：CPLD 像 Board-Level 即時邏輯管家，負責 power、reset 與離散訊號的確定性控制；BMC 像管理中樞，負責策略、紀錄、對外管理與韌體更新。CPLD 不取代 BMC，兩者通常互相配合。

SMC 是什麼

這裡的 SMC 指 ASPEED Satellite Management Controller，屬於 server management 用的 Bridge IC。以 AST1040 SMC 為例，它是第二代 Satellite Management Controller，用於可擴充的 multi-node server management、OCP Streaming Boot 架構，以及透過 USB 進行 OBMF-ICP 管理連線。

Satellite Controller

作為 BMC 周邊的 satellite / bridge controller，協助擴展多節點與多模組管理能力。

新世代管理橋接

支援 OCP Streaming Boot 與 OBMF-ICP over USB，適合新世代 rack-scale server 架構。

安全與控制

AST1040 具備 Caliptra 2.x integrated RoT、physical anti-tamper，並提供多節點管理所需的控制與連線能力。

項目BMCSMC
定位整機或節點的主要管理控制器，通常具備網路管理介面與完整管理韌體。Satellite Management Controller / Bridge IC，輔助 BMC 擴展 multi-node、模組化與 rack-scale 管理。
常見功能Redfish/IPMI、KVM/SOL、sensor、event log、firmware update、遠端維運。OCP Streaming Boot、OBMF-ICP over USB、LTPI 連線、RoT 安全能力、多節點管理橋接。
代表晶片ASPEED AST2600、AST2700 等 BMC SoC。ASPEED AST1040 SMC，內建 ARM Cortex-M4、Flash/RAM、USB、LTPI 與 Caliptra RoT。
簡單理解：BMC 是主要管理中樞；AST1040 這類 SMC 是 BMC 周邊的 satellite / bridge controller，用來把新世代多節點、模組化與 rack-scale server 的管理連線擴展出去。

BIC 與 SMC 的關係

BIC 是 Bridge IC，代表晶片如 ASPEED AST1030 / AST1035。它是 BMC 的 local agent / bridge，常放在 server card、node、tray 或模組上，協助 BMC 延伸多節點與模組化管理能力。

項目BICSMC
代表晶片AST1030、AST1035AST1040
核心角色BMC 的 Bridge IC / local agent。新一代 Satellite Management Controller，延續 bridge/local-agent 角色。
平台重點多節點 server、server card、模組化系統管理延伸。multi-node server management、OCP Streaming Boot、OBMF-ICP over USB、LTPI、Caliptra RoT。
嚴謹理解：SMC AST1040 不是單純把 BIC 改名，而是延續 BIC 的橋接/代理角色，並加入新世代 OCP、rack-scale、boot fabric 與安全管理能力。

BMC 與 SMC 怎麼連接溝通

BMC 與 AST1040 SMC 的連接通常會分成 管理資料通道 與 硬體控制 sideband。資料通道負責韌體、管理訊息與大量狀態資料；sideband 則負責 reset、interrupt、presence、boot strap、錯誤告警等即時硬體訊號。

連接方式角色常見用途
OBMF-ICP over USB主要管理資料通道BMC 透過 USB 與 SMC 交換 OBMF-ICP 管理資料，可用於模組管理、韌體流程或較高層的管理通訊。
LTPI低腳位數平台介面延伸把遠端節點或模組上的低速平台訊號延伸回管理端，例如 GPIO 類控制、狀態、告警或平台 sideband 訊號。
I2C / SMBus低速管理匯流排讀取 board ID、FRU、sensor、EEPROM、簡單狀態暫存器，或和板上 MCU/CPLD 做低速控制。
GPIO / Interrupt即時硬體 sidebandreset、power good、presence detect、fault、alert、boot done、tamper 等單一事件或控制訊號。
UART / Debug Port除錯與製造支援開發、bring-up、工廠測試或故障分析時使用，不一定作為正式管理資料通道。
實務心智模型：BMC 負責對外管理與決策；SMC 靠近被管理的節點或模組，負責橋接與現場訊號收斂。兩者之間通常以 USB/LTPI 承載主要管理連線，再搭配 I2C/SMBus、GPIO、interrupt 等 sideband 訊號完成硬體控制。

對應新世代 AI 晶片與 Rack-scale 平台

在 NVIDIA Grace Blackwell、GB200/GB300 NVL72、AI rack、DPU / SuperNIC 等新世代平台中，管理架構逐漸從「一顆 BMC 管整台 server」演進成 多控制器分層管理。BMC 仍是對外的主要 out-of-band 管理入口，但 tray、switch、power shelf、DPU、液冷模組等子系統常會有自己的管理控制器。

Compute Tray / HMC

GPU compute tray 可能搭配 Host Module Controller，協助 BMC 管理 Grace CPU、Blackwell GPU、tray inventory、LED、reset 與子板狀態。

BMC + SMC 拓撲

新平台可由 BMC SoC 搭配 AST1040 這類 SMC，將管理面延伸到多節點、GPU tray、boot fabric 與模組化子系統。

Power / Cooling Controller

Power shelf、PMC、CDU、pump、valve、flow/leak sensor 會形成獨立控制迴路，再把健康狀態與告警回報給 BMC 或 rack manager。

新世代平台的心智模型：BMC 是對外管理入口；SMC/HMC/PMC/MCU 是分散在各模組上的現場控制器；Rack Manager 或資料中心管理軟體再把多台、多 tray、多 switch、多 power shelf 的資訊收斂成整櫃視角。

SECTION 6

常見管理介面與協定

DMTF 是什麼

DMTF 是 Distributed Management Task Force，為制定 IT 基礎架構、伺服器、資料中心與平台管理標準的產業標準組織。

DMTF 定義管理標準，BMC 實作這些標準，管理平台再透過這些標準控制與監控伺服器。

OCP 與 OBMF-ICP 的定位

OCP 是 Open Compute Project，由資料中心與硬體生態系共同推動開放硬體規格。相較於 DMTF 偏向管理資料模型與協定標準，OCP 更偏向 rack、server、tray、power、cooling、boot 與可維修性等開放硬體平台規格與實作生態。

OCP

開放硬體與資料中心平台規格生態，常見焦點包含 rack-scale、模組化節點、電源、散熱、管理與可維修性。

OBMF-ICP

可理解為 Open Boot Management Framework 的 inter-control-plane 管理通道，用於 BMC 與 SMC / satellite controller 之間交換 boot、管理與控制相關資料。

Streaming Boot

在 OCP Streaming Boot 架構中，boot image 或 boot flow 可透過管理/控制平面被協調，適合無本地儲存或模組化的大規模平台。

名詞重點在 BMC / SMC 架構中的意義
OCPOpen Compute Project，開放資料中心硬體規格與生態。定義或推動 rack-scale、模組化、可互通與易維護的平台設計方向。
OCP Streaming Boot以集中式或網路化方式協調 boot image / boot flow。SMC 可協助節點或模組參與 boot fabric，讓 BMC / rack manager 能管理開機流程與狀態。
OBMF-ICP over USBBMC 與 SMC 之間的高層管理資料通道，實體媒介常見為 USB。承載 OBMF-ICP 訊息，交換模組狀態、boot/control 資訊、韌體流程資料與管理命令。
簡單理解：DMTF 偏向「管理資料與協定怎麼標準化」；OCP 偏向「開放硬體平台與 rack-scale 架構怎麼設計」；OBMF-ICP over USB 則是 BMC 與 SMC 之間承載 boot / control 管理資料的重要通道。

MCTP / PLDM 定位

SPDM 的定位

SPDM 是 Security Protocol and Data Model，用於平台內部元件的身份驗證、量測驗證與安全通道建立。常見 requester 是 BMC 或 host，responder 則可能是 NIC、GPU、CXL device、SSD、retimer、accelerator 等裝置。

Certificate

驗證裝置身份，確認裝置是否來自可信任廠商或平台。

Measurement

驗證裝置 firmware、boot state、configuration 是否符合安全政策。

Challenge

確認裝置持有對應私鑰，避免偽裝裝置。

Secure Session

建立具加密與完整性保護的管理通道。

名詞角色
MCTP管理訊息的傳輸層。
PLDM管理資料模型，例如 sensor、FRU、firmware update。
SPDM安全驗證與安全 session。
MCTP 解決訊息怎麼送，PLDM 解決資料怎麼表達，SPDM 解決裝置是否可信與通訊是否安全。

BMC 核心心智模型

問題答案
BMC 管什麼？電源、感測器、風扇、事件、console、firmware、遠端管理。
BMC 何時能工作？只要 standby power 存在，通常 host 關機也能工作。
CPLD 和 BMC 差在哪？CPLD 執行低延遲、確定性的 Board-Level 硬體邏輯，例如 power/reset sequencing、GPIO 與 fault 處理；BMC 執行管理韌體，負責監控、決策、紀錄與遠端維運。
SMC 和 BMC 差在哪？BMC 是主要管理中樞；AST1040 這類 SMC 是 Satellite Management Controller / Bridge IC，用來擴展 multi-node、模組化與 rack-scale 管理連線。
OCP 在這裡指什麼？Open Compute Project，偏向開放硬體規格與資料中心平台生態，不是單一 BMC 協定。
OBMF-ICP over USB 是什麼？BMC 與 SMC / satellite controller 之間的高層管理資料通道，可承載 boot、控制、模組狀態與韌體流程相關訊息。
OpenBMC 對外主要 API？Redfish。
OpenBMC 內部主要 IPC？D-Bus。
OpenBMC 怎麼建構？Yocto + BitBake。
新板子最常改哪裡？DTS、machine config、sensor config、GPIO、fan policy、recipe。
