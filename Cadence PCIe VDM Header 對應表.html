Cadence PCIe VDM Header 對應表

軟體先準備完整的 TLP Header Buffer（hdr_byte0~15）與 payload； 硬體再從 buffer 取出各欄位，轉寫到 Cadence Region Descriptor、 VDMTAG、AXI AWADDR 與 transfer length，最後觸發 VDM 傳送。 下表依 Header Byte 順序說明每個軟體欄位會被硬體用在哪裡。

SW Header Buffer 建議初始值

下表是目前 MCTP VDM 送出流程的建議起始值。標示「依封包填入」的欄位不能固定為 default； SW 應先完成 hdr_byte0~15，硬體只負責取值與轉寫。

SW Header 欄位 建議值 使用原則
hdr_byte0[7:5] / Fmt 3'b011 一般 MCTP VDM 帶 data，使用 4-DW Header with Data；無 data 時改為 3'b001。
hdr_byte0[4:3] / Message Type 2'b10 PCIe Message Request 的 Type 高 2 bit；Routing 另由低 3 bit 指定。
hdr_byte0[2:0] / Routing 3'b010 MCTP 常用 Route by ID；硬體將此值放入 AWADDR[14:12]。
hdr_byte1[6:4] / TC 3'b000 沒有特別 QoS 需求時使用 Traffic Class 0。
{hdr_byte1[2], hdr_byte2[5:4]} / Attr 3'b000 沒有 Relaxed Ordering、No Snoop 或其他 attribute 需求時清 0。
hdr_byte2[7] / TD 1'b1 目前流程要求插入 ECRC 時設 1；硬體以此值設定 desc0[21]。若不使用 ECRC，SW 與硬體必須同步改為 0。
{hdr_byte2[1:0], hdr_byte3[7:0]} / Length ceil(payload_bytes / 4) 單位是 DW；例如 64-byte payload 填 10'h010。不足 4 bytes 的尾端由 Pad Length 描述。
hdr_byte4~5 / Requester ID 依實際 BDF 填入 Byte 4 是 Bus；ARI 時 Byte 5 全部是 Function，Non-ARI 時 Byte 5 為 Device[4:0] + Function[2:0]。
hdr_byte6 / VDMTAG 8'h00 VDM Code 0、Pad Length 0；payload 非 DWORD 對齊時，依實際 padding 更新 Pad Length。
hdr_byte7 / Message Code 8'h7F 目前流程建議 Type 1 VDM；若平台要求 Type 0 VDM，改為 8'h7E。
hdr_byte8~9 / PCI Target ID 依目標 BDF 填入 Route by ID（3'b010）時必須填目標端的 Bus/Device/Function；其他 routing 模式此欄位為 reserved，填 16'h0000。
hdr_byte10 / Vendor ID[15:8] 8'h1A 固定值。DSP0238 規定 MCTP over PCIe VDM 的 Vendor ID 必須是 DMTF 的 0x1AB4，填錯對端不會將此封包辨識為 MCTP。
hdr_byte11 / Vendor ID[7:0] 8'hB4 固定值，同上；wire 上為 big-endian，故 0x1A 在 Byte 10、0xB4 在 Byte 11。
hdr_byte12 / RSVD + Hdr Version 8'h01 固定值。[7:4]=RSVD 填 0，[3:0]=MCTP Header Version 目前為 4'b0001。
hdr_byte13~14 / EID 依目標端填入 Byte 13 = Destination EID，Byte 14 = Source EID；由 MCTP endpoint 位址決定，無固定預設值。
hdr_byte15 / flags + tag 依封包填入 SOM / EOM / Pkt Seq[1:0] / TO / Msg Tag[2:0]；由分段狀態與 message tag 決定，無固定預設值。
Cadence 本地控制值（不屬於 PCIe Header Buffer）
  1. desc0[3:0] = 4'hD：宣告此 outbound region 為 Vendor Message。這是硬體定義的 selector，不照 PCIe Header bit 編碼填寫，也不是 0x2。
  2. desc0[23] = 1'b1：使用 SW Header Buffer 提供的 Requester ID。
  3. desc2[31:0] = 32'h0：目前不使用 TPH。
  4. region_num = 1：建議從第一個可用 region 開始；region #0 保留。它是本地 metadata，不在 TLP Header Buffer 內。

MCTP Payload 的 AXI WDATA Byte Order

MCTP payload 依 memory 中的 byte 順序放進 AXI WDATA[127:0]，不另外反轉 byte。 payload_byte0 放在最低 8 bit，後續 byte 依序放到更高的 byte lane； 因此 payload_byte0 同時是 wire 上 Header Byte 16 的 MCTP Message Type。

// AXI WDATA byte lanes follow the byte order in memory.
AXI_WDATA[127:0] = {payload_byte15,  // [127:120]
                     ...,
                     payload_byte3,   // [31:24]
                     payload_byte2,   // [23:16]
                     payload_byte1,   // [15:8]
                     payload_byte0};  // [7:0], lowest-addressed byte

Byte lane 對應：payload_byte0 → AXI WDATA[7:0]， payload_byte15 → AXI WDATA[127:120]。 這裡的 little-endian 指的是 byte-lane placement；AXI WDATA 的 byte 順序應與 memory 中的 byte 順序相同。

如何送出一個 VDM

SW 先完成 hdr_byte0~15 與 payload buffer；接著硬體把 Header Buffer 轉寫成 Region Descriptor 與 VDMTAG，並從 Fmt、Message Code、Routing、Length 解出本次 AXI transaction 的控制值。 最後對該 region 的 Outbound Window 做一次 AXI Write，由 Cadence IP 送出相同內容的 VDM TLP。

送出序列

硬體轉寫 Region Descriptor

SW 已先備妥 Header Buffer。硬體選一個 region N（N = 1~31；region 0 在 PCIe EP0 為保留，不可用），把對應欄位寫進 TLP_BASE + 0x40·N（simulation code：64*region_num，每 region 間隔 64 bytes）。其中 transaction_type=0xD 是 Cadence 硬體要求的 VDM selector，不是從 PCIe spec header 直接複製。

// TLP_BASE = 0x1C12_0000 (= 0x1C10_0000 + 0x2_0000) ;  base = TLP_BASE + 0x40*N

// desc0 @ +0x08 : VDM selector + Requester ID + attr（RMW：保留 [22],[20],[16],[7]）
wdata        = APB_RD(base+0x08);
wdata[31:24] = hdr_byte5[7:0];       // ARI: Function[7:0]；Non-ARI: Device[4:0] + Function[2:0]
wdata[23]    = 1'b1;                 // requester_id_sel（控制位，不對應 hdr_byte）
wdata[21]    = hdr_byte2[7];         // TD / force ECRC insert
wdata[19:17] = hdr_byte1[6:4];       // TC
wdata[15:8]  = hdr_byte8[7:0];       // vendor_defined_info = vdm_95_72[31:24]
wdata[6:4]   = {hdr_byte1[2],        // Attr[2]
                hdr_byte2[5:4]};     // Attr[1:0]
wdata[3:0]   = 4'hD;                 // Cadence Vendor Message selector；不是 TLP header 欄位
APB_WR(base+0x08, wdata);

// desc1 @ +0x0C : Bus number（RMW：保留 [31:8]）
wdata      = APB_RD(base+0x0C);
wdata[7:0] = hdr_byte4[7:0];         // Bus number
APB_WR(base+0x0C, wdata);

// desc2 @ +0x10 : 整個寫 0（TPH 不用）
APB_WR(base+0x10, 0x0);

// addr0/addr1 @ +0x00/+0x04 : VDM 時＝VDM header bytes（非記憶體位址）
//   little-endian：register 低位 byte = wire 上較前面的 header byte
//   addr0[15:8]=B9 [23:16]=B10 [31:24]=B11（[7:0]=reserved 填 0）
//   addr1[7:0]=B12 [15:8]=B13 [23:16]=B14 [31:24]=B15
APB_WR(base+0x00, (hdr_byte11<<24)|(hdr_byte10<<16)|(hdr_byte9<<8));
APB_WR(base+0x04, (hdr_byte15<<24)|(hdr_byte14<<16)|(hdr_byte13<<8)|hdr_byte12);

RTL bit-slice 版本（含完整 RMW 寫法）見 Cadence PCIe VDM Header 對應表_DD_RTL.txt。

硬體轉寫 VDMTAG

Vendor Defined Message Tag register 的 index 是 0x56，Management APB byte address 是 0x158。低 8 bit 放 VDM Code 與 Pad Length，上方 24 bit 填 0，完整寫入 32 bit、不需 RMW。Payload 已 DWORD 對齊時可使用 tag=0，代表 VDM Code 0、Pad Length 0；否則 SW 必須依實際 padding 更新 Header Byte 6。

// Access Vendor Defined Message Tag Register (index 0x56, byte addr 0x158)
apb_addr = APB_BASE + 32'h0001_0000 + 32'h0000_0158;
tag[7:0] = hdr_byte6[7:0];           // VDM Code / RSVD / Pad Length
wdata    = {24'h0, tag[7:0]};        // complete 32-bit write; no RMW
sim.app.mgmt_apb_wr(apb_addr, wdata);

觸發送出：一次 AXI Write

對 region N 對應的 Outbound Window 做一筆 AXI 寫入。硬體從 Header Buffer 解出 Message Code、routing 與 transfer length，並把 payload 放入 AWDATA；Cadence IP 再依轉寫結果送出對應的 VDM TLP。

// AWADDR[39:35] : Region_Sel = N（1~31；region 0 保留）
zero_data = (hdr_byte0[7:5] == 3'b001); // Fmt: 4-DW Header without Data
code_sel  = hdr_byte7[0];             // 0→0x7E(Type0) / 1→0x7F(Type1)
route     = hdr_byte0[2:0];           // Message Routing
length_dw = {hdr_byte2[1:0], hdr_byte3[7:0]};
len       = zero_data ? 0 : ((length_dw == 0) ? 4096 : length_dw * 4);
// AWDATA        : MCTP message + payload；payload_byte0 → WDATA[7:0]，byte order 與 memory 相同
AXI_WR(SLV_BASE | ((uint64_t)N<<35)
                | (zero_data<<16) | (code_sel<<15) | (route<<12),
       payload, len);
// → IP emit VDM TLP；SLV_BASE = controller AXI slave port 在 SoC address map 的落點
設計注意事項（2026-07）
  1. outbound_window(N) base 由 AWADDR[39:35]=N 決定， 即 SLV_BASE + N×2³⁵（每 region 間隔 32 GB）。 5'b00001~5'b11111 皆指到 PCIe EP0，因此可用 region 為 #1~#31，region #0 保留。
  2. Code-select bit 為 AWADDR[15]。
  3. TX done / busy / error 狀態位於 DMA control registers（確切 offset 待查 spec）。
  4. AXI Mgmt Reg 13 @0x434 不需設定，維持 default 0。
  5. AWDATA / payload 採 little-endian byte-lane placement： payload_byte0 → WDATA[7:0]，整體 byte 順序與 memory 相同。
  6. VDMTAG register index 為 0x56，Management APB byte address 為 0x158；以 {24'h0, tag[7:0]} 完整寫入 32 bit。
